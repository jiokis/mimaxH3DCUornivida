# 第一部分：工作流汇总

## 1. 管线总览（四阶段）

```
┌─ 阶段1 base 480p 生成 ────────────────────────────────────┐
│ h3_gen_wire_fixed.py <prompt> video/<tag>_base \          │
│   20 <帧数> <seed> simple max furina_single 864 480 dotted│
│ · 864×480 / 20 步 / res_multistep+simple / CFG 1.0        │
│ · 点号参考图接线 ref_images.ref_image_0                    │
│ · 落盘确认（>1MB 且连续两次大小相同）                       │
│ · 产出：完整多镜视频 + H3 原生音轨（AV 联合生成）           │
└───────────────────────────────────────────────────────────┘
                          ↓
┌─ 阶段2 切段 ──────────────────────────────────────────────┐
│ · 切点检测（当前：scene 0.15 / 升级中：三信号融合）         │
│ · 伪切点过滤（间隔 <24 帧合并，防闪电/光效误检）            │
│ · 暗场景兜底（检出 <3 段时按 ~73 帧均分）                   │
│ · 网格算法：grid_nearest + 最小段保护(≥39) + 大段缩124     │
│              + 余量传递 → Σ段帧数 ≈ base 帧数（误差≤3帧）  │
│ · 切段命令：-ss <起点> -t <时长>（音视频等长）             │
└───────────────────────────────────────────────────────────┘
                          ↓
┌─ 阶段3 二采 1728×960 ─────────────────────────────────────┐
│ twopass_gen.py <prompt> video/tp_<tag><n> <seg>.mp4 \     │
│   1728 960 4 0.2 beta <seed> furina_single <段帧数>       │
│ · 4 步 / beta / denoise 0.2（像素空间放大后重采样）        │
│ · 每段 ≤124 帧（960p 安全上限，避开帧数悬崖）              │
└───────────────────────────────────────────────────────────┘
                          ↓
┌─ 阶段4 拼接（音床合流法）─────────────────────────────────┐
│ 1) 视频单独 concat（-c:v copy -an）零漂移                  │
│ 2) 音轨用 base 完整音轨（音床）整体合流                    │
│ 3) tpad 补帧对齐音床时长 → 音乐完整收尾不截断              │
│ 4) 段完整性校验（缺段拒绝拼接，产出 INCOMPLETE 标记）      │
└───────────────────────────────────────────────────────────┘
```

## 2. 关键参数（硬约束）

| 项 | 值 | 原因 |
|---|---|---|
| 帧数网格 | **17n+5**：22/39/56/73/90/107/124/141/362 | H3 训练网格，越界静默吸附 |
| CFG | **1.0** | H3 guidance-distilled，调高无益 |
| 二采步数 | 4（beta 调度器）| denoise 0.2 提分辨率，不改内容 |
| base 分辨率 | 864×480 | DCU 上 20 步 ≈ 140s/it |
| 二采分辨率 | 1728×960 | 头高 ≥200px 脸才稳定可用 |
| 段帧数上限 | **124** | 960p 下 124帧=192s/it，192帧=1504s/it |
| 启动参数 | `--highvram` + `HIP_VISIBLE_DEVICES=0` | DCU 必需 |
| 时长换算 | 24 fps；362帧=15.08s，345帧=14.375s | |

## 4. 已知缺陷与修复记录

| # | 缺陷 | 根因 | 修复 | 状态 |
|---|---|---|---|---|
| 1 | DCU 卡不工作（HCU=0）| HIP 未显式指定设备，算子回退 CPU | `HIP_VISIBLE_DEVICES=0` | ✅ |
| 2 | 59GB 内存撞顶 | `--lowvram` 权重驻留 CPU | `--highvram` 权重进显存 | ✅ |
| 3 | 15s 裁成 12s | `grid_floor` 向下取整每段丢 5-16 帧 | `grid_nearest`+余量传递 | ✅ |
| 4 | 二采慢 8 倍（812s/it）| 切出 138 帧悬崖段 | 大段缩到 124 | ✅ |
| 5 | 产出 9.33s 残片 | 段5 超时缺失仍拼接 | 段完整性校验 | ✅ |
| 6 | base 48B 坏文件 | SaveVideo 异步写未完成 | 落盘确认 + >1MB 校验 | ✅ |
| 7 | **切点不对齐（错误帧进二采）** | **scene 检测 ≠ 模型镜头边界** | **三信号融合（进行中）** | ⚠️ |
| 8 | 音轨不同步 | 每段 AAC 填充 832 采样累积漂移 | 音床整体合流 | ✅ |
| 9 | 重跑拼到旧文件 | SaveVideo 序号递增 _00002_ | 待修（拼最新序号）| ⚠️ |

### 缺陷 #7 详解（当前最大短板）
- **现象**：红烧肉提示词设计 7 镜，scene 检测仅 4 切点，位置偏差 0.6-1.5s
- **后果**：过渡帧（镜头A尾+镜头B头）被切进段，二采在错误内容上发挥
- **修复方案**：`detect_cuts.py` 三信号融合（scene + 帧差 + **音频 RMS 突变**）+ 切点吸附稳定帧
- **洞察**：H3 是 AV 联合生成 → **音频边界 = 镜头边界**（音景变化不受画面相似性影响）

## 5. 验收方法（量化，不靠肉眼）


# 第二部分：提示词构建汇总

## 1. 模式选择

| 场景 | 模式 | 结构 |
|---|---|---|
| **参考图绑定**（角色/场景卡）| **Ref2VA** | 六段式 |
| 首帧起（同场景续接）| I2VA | 对齐指令 + 三段 |
| 首末帧（转场镜）| FL2VA | 对齐指令 + 三段 |
| 纯文本 | T2VA | 三段 |

本工程全部用 **Ref2VA 六段式**（角色一致性靠 furina_single.png 参考图）。

## 2. 六段式结构（字段名/顺序不可改）

```text
subject_definitions     角色与场景定义（参考图以 <Picture 1> 引用）
summary                 整片概述（镜数/弧线/音乐结构声明）
retention_analysis      引用项保留声明（fully_preserved + 出现位置）
detailed_description    逐镜详述（风格 + 构图纪律 + [Shot N]×N）
overall_soundscape      环境音/动作音/非语言人声
non_diegetic_music      配乐（乐器/音区/速度/织体/力度）
```

### 各段写作要点

**subject_definitions**
- 角色：`<Subject 1> (S1) is Furina..., whose exact design is shown in <Picture 1>`
- 必须逐项写死身份锚点：异色瞳（右冰蓝/左深紫罗兰）、一手黑一手白手套、帽饰、
  金边外套、胸前腰间双蝴蝶结、大腿绑带、脚踝短靴
- 场景：`<Subject 2> is ...` 含光线/道具/色调，**末尾声明无开阔背景**
- 仅定义角色的图**不单独建 `<Picture N>` 条目**，在 `<Subject N>` 里引用

**summary**
- `[reference generation]` 开头
- 一句话概述 + 镜数 + 每镜核心动作 + 音乐结构 + `never serves as a concrete frame anchor`

**retention_analysis**
- 每项：出现位置 + `fully_preserved`
- **只定义身份与服装，绝不写姿态**（写姿态会锁死动作导致崩坏）
- 本节内不得出现 `(Sx)`

**detailed_description**（最重）
- 首段：风格锁（`official Genshin Impact anime style: cel-shaded...`）+ **构图纪律**
- 每镜 `[Shot N]`：
  1. 景别与构图（`A tight medium close-up of <Subject 1> from the collarbone up`）
  2. 主体位置与外观（含异色瞳可读性）
  3. 环境与光照
  4. 动作与表情（**物理描述**：眉头/嘴角/闭眼/呼吸）
  5. **运镜**（类型 + 幅度 + 速度）
  6. 当前声音（diegetic）
  7. 口型纪律（`She does not speak; her lips stay closed.`）

**overall_soundscape**
- 1–4 句，逐镜列环境音/动作音
- 不重复台词/歌唱/diegetic 音乐

**non_diegetic_music**
- 1–3 句，**五段式完整结构**（引入→发展→高点→收束）
- 只写乐器/音区/速度/织体/力度，**禁抽象情绪词**
- 末句 `never cut off` + 长音完整衰减

## 3. 四条铁律（违反即废片）

1. **帧数 17n+5**（22/39/56/73/90/107/124/141/362）
2. **CFG 1.0**
3. **深度控制 strength ≈0.3**（本工程未用深度控制）
4. **必须用官方字段名**（写散文会明显降质，尤其配乐）

## 4. 构图纪律（角色呈现的核心）

### 画幅占比定律（受控实验验证）
| 景别 | 头占画幅 | 头高（绝对像素）| 面部结果 |
|---|---|---|---|
| 全景全身 | ≈1/8 | ≈90px | ❌ 空白椭圆 |
| 中景 | ≈1/3 | ≈140px | ⚠️ 有五官但表情不稳 |
| **中近景** | **≈1/2** | **≈210px** | ✅✅ 完全可用 |

- **中景（头≥1/3）= 安全下限**
- 决定因素是**头部绝对像素数**，不是画幅占比（推近与提分辨率是同一杠杆的两个旋钮）
- **任何细节占比过小即崩**（远景下的手/道具/食物同样崩）

### 关键不对称
- 要「全景」→ 一次到位（模型先验偏向全景）
- 要「近景」→ 被完全无视（文本压不住构图）
- **解法：消除全景余地**（每镜写成物理上无法拍全景：近景+压黑背景+无开阔环境）
- 必须全景时 → 让角色**低头/背身/侧身/剪影**，不让空白脸正面朝镜头

### 本工程的构图策略
```
FRAMING 段声明三类镜位配额（如 4 近景 + 2 全身侧面 + 1 手部特写）
每镜显式声明景别 + "No face is in frame" / "face turned away"
NEG 末尾追加 "或 wide/establishing shot"（注意：H3 无负向通道，此处是风格约束）
```
实测有效：蛋炒饭 9 镜（6 角色 + 3 工序特写）、水之环舞 6 镜全有脸。

## 5. 运镜语言（官方词表）

| 类型 | 官方词 |
|---|---|
| 镜头 | Zoom In/Out、Push In/Pull Out、Pan Left/Right、Truck Left/Right、Tilt Up/Down、Pedestal Up/Down、Arc Shot、Tracking Shot、Static Shot、Shake Slightly/Strongly、POV、Roll CW/CCW |
| 幅度 | `with small amplitude` / `with large amplitude` |
| 速度 | `at slow speed` / `at fast speed` |

句式（自然英语，不堆标签）：
```text
The camera pushes in with small amplitude at slow speed toward the folded letter.
```

### 生动化原则（本工程实践）
- **每镜运镜与动作/情绪绑定**，拒绝全片 static
- 例：颠勺时镜头随节奏起伏（arc shot）、目光移动带动横摇、蒸汽/水流作运镜参照物
- 避免重复（蛋炒饭 v1 有 3 处 push-in → v2 改为 9 种不同运镜）

## 6. 音频三段分工（最易写错）

| 字段 | 写什么 | 不写什么 |
|---|---|---|
| `detailed_description` 内 | 台词、歌唱、**diegetic** 声音（角色能听见的）| — |
| `overall_soundscape` | 环境音、物理动作音、非语言人声 | 不重复台词/歌唱 |
| `non_diegetic_music` | **仅观众听到的配乐**：乐器/速度/节奏/动态 | 禁抽象情绪词，不解释情绪功能 |

配乐写法对比：
- ✅ `Sparse piano notes at a slow tempo, joined by sustained low strings...`
- ❌ `温馨感人的音乐`

## 7. 台词与字幕规则

### 台词
```text
The young woman with a quiet, breathy voice (S1) says: <d>[Chinese] 我下班了。</d>
```
- 说话人用稳定 ID `(S1)`，首次出现建立身份（类型/年龄/性别/音高/音色/语速）
- 台词逐字放在 `<d>[语言] ...</d>`，不翻译不改写
- 旁白用 `says in an off-screen voiceover` + 声明嘴唇闭合
- **单块台词 ≤16 字**（12–13 字逐字精确，≥18 字必须拆镜）

### 字幕（四条缺一不可）
1. 声明**紧贴对白句**（不放末尾）
2. `reading exactly "字幕原文"`（逐字含标点）
3. `with a subtle dark outline for legibility`（强调描边）
4. **只给结束点** `fades out gently by about 4.0 seconds`（**不给时间窗**）

❌ 失败写法：给时间窗 / 台词 1.0s 才起（长前摇）/ 中文指令句
