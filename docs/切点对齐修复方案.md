# 切点对齐修复方案（镜头切点 vs 场景检测偏差）

## 问题
当前 run_theme.sh 用 ffmpeg `select=gt(scene,0.15)` 检测切点，
但 H3 模型的镜头边界是内容级（人物/场景/构图），像素差检测存在：

1. **漏检**：镜头切换但画面相似（暗场景/同机位）→ 两镜并一段 → 段内容不纯
2. **误检**：非切点的剧烈变化（闪电/快速移动）→ 一镜拆两段 → 碎段
3. **漂移**：检到过渡帧而非干净切点 → 段含跨镜混合帧 → 二采在错误帧上发挥

**实测证据**（红烧肉 16:39 轮）：
- 提示词设计 7 镜（切点应 ~2.15/4.3/6.45/8.6/10.75/12.9s）
- 场景检测仅 4 个切点 [38,108,177,222]（1.58/4.5/7.38/9.25s）
- 偏差 0.6-1.5s → 段边界落在过渡区，错误帧投入二采

## 修复方案（三信号融合 + 切点对齐）

### 层 1：三信号切点检测（替代单一 scene）

| 信号 | 命令 | 补谁 |
|---|---|---|
| A. scene 像素差 | `select=gt(scene,0.15),showinfo` | 基线 |
| B. 光流/运动突变 | `select=gt(motion,阈值)`（需 libmotion 或双帧差分）| 补 A 漏检 |
| C. 音频边界 | `astats=metadata=1,ametadata` 提取 RMS → 找突变 | **最可靠**（AV 联合生成，音景变化=镜头边界）|

**融合规则**：
- 三信号一致 → 高置信切点（直接用）
- 两信号一致 → 中置信（保留，需层2验证）
- 单信号 → 丢弃

**实现**（python，在切段段内嵌）：
```python
def detect_cuts(v, ff):
    # A: scene 像素差
    cuts_a = scene_detect(v, ff, 0.15)
    # B: 帧差分（两帧间绝对差，取峰值）
    cuts_b = framdiff_peaks(v, ff, window=5)
    # C: 音频 RMS 突变（每 0.5s 窗口，找 >2σ 突变）
    cuts_c = audio_rms_breaks(v, ff, window_sec=0.5)
    # 融合：时间轴对齐（±3 帧内视为同一候选）
    return fuse([cuts_a, cuts_b, cuts_c])
```

### 层 2：切点对齐（过渡帧规避）
每个候选切点 ±5 帧内，找**画面最稳定帧**（与相邻帧差最小）作为实际切点：
```python
def snap_to_stable(c, v, ff, radius=5):
    best, best_diff = c, 1e9
    for f in range(c-radius, c+radius+1):
        d = framdiff(v, f-1, f) + framdiff(v, f, f+1)
        if d < best_diff:
            best, best_diff = f, d
    return best
```

### 层 3：段纯净度校验（兜底）
切段后每段内部一致性检查：
```python
def purity_check(seg, ff, threshold=0.08):
    # 段内最大相邻帧差
    intra = max_framdiff(seg)
    # 段平均帧差
    mean = avg_framdiff(seg)
    return (intra - mean) < threshold  # 段内突变过大 = 混入过渡/双镜头
```
不纯净段 → 标记重切（在该段内再找切点拆分或丢弃）。

## 验证方法
1. 对同一 base，对比 scene 检测 vs 三信号融合的切点数量/位置
2. 用**音频边界**做基准（AV 联合生成的镜头边界 = 音频变化点）
3. 检查融合后切点是否对齐提示词设计的 [Shot N] 时间（±0.3s 内）
4. 段纯净度：切点吸附后，段首尾帧应属同一镜头（目视/帧差验证）

## 附带：音频边界为什么可靠
H3 是 AV 联合生成：每镜的 overall_soundscape 不同（切菜声/油锅声/翻炒声），
镜头切换必然伴随音景突变。音频 RMS/频谱变化是**内容级**信号，不受画面相似性影响。
这是对 scene 检测（纯像素）的根本性补充。
